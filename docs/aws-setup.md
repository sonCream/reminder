# AWS 콘솔 설정 절차

AWS 웹 콘솔에서 손으로 하는 작업만 모았다.
여기까지 끝나면 서버에 접속할 수 있는 상태가 되고, 그다음은 [deploy.md](./deploy.md)로 이어진다.

**순서를 지켜야 한다.** 탄력적 IP가 나와야 DNS를 신청할 수 있고, DNS 신청은 사내 결재가 걸릴 수 있어 가장 먼저 착수해야 한다.

```
① EC2 생성 → ② 탄력적 IP → ③ DNS 신청 → ④ RDS → ⑤ Docker 설치 → deploy.md
                              └ 대기가 생기는 구간. 최대한 빨리 신청할 것
```

## 0. 시작 전

⚠️ **우측 상단 리전이 `아시아 태평양(서울) ap-northeast-2`인지 확인한다.**

리전은 서비스마다 완전히 분리돼 있다. 다른 리전에 만든 리소스는 목록에 아예 보이지 않는데 **요금은 그대로 나간다.** "분명 만들었는데 목록이 비어 있다"의 원인은 거의 항상 이것이다.

## ① EC2 인스턴스 생성

**EC2 → 인스턴스 → 인스턴스 시작**

| 항목 | 값 |
|---|---|
| 이름 | `reminder-app` |
| AMI | **Ubuntu Server 24.04 LTS** |
| 인스턴스 유형 | **t3.small** |
| 키 페어 | 새로 생성 → `.pem` 다운로드 후 보관 |
| 스토리지 | gp3 **20GB** |

⚠️ **t3.micro를 고르지 말 것.** 메모리 1GB로는 `next build`가 도중에 죽는다. 프리티어를 아끼려다 원인을 못 찾고 반나절을 날리는 대표적인 함정이다.

⚠️ **`.pem` 키를 잃어버리면 서버에 영원히 못 들어간다.** 다운로드 즉시 안전한 곳에 복사해둔다.

**보안 그룹** — 새로 생성하고 인바운드 규칙 3개를 넣는다.

| 포트 | 소스 | 용도 |
|---|---|---|
| 22 (SSH) | **내 IP** | ⚠️ `0.0.0.0/0` 금지 |
| 80 (HTTP) | 위치 무관 | Let's Encrypt 인증서 발급에 필요 |
| 443 (HTTPS) | 위치 무관 | 서비스 |

80을 막으면 인증서 발급이 실패하므로 열어둬야 한다.

## ② 탄력적 IP 할당 및 연결

**할당**과 **연결**이 별개 단계다. 여기서 자주 막힌다.

**EC2 → 좌측 메뉴 `네트워크 및 보안` → `탄력적 IP`**

> 좌측 메뉴에서 안 보이면 아래로 스크롤한다. `인스턴스` 그룹이 아니라 **`네트워크 및 보안`** 그룹에 있다.

### 2-1. 주소 할당

우측 상단 **`탄력적 IP 주소 할당`** → 기본값 그대로 → **`할당`**

### 2-2. 인스턴스에 연결

1. 목록에서 할당된 IP의 **왼쪽 체크박스를 클릭**해 선택한다
   (행을 클릭하는 게 아니라 네모를 눌러야 `작업` 버튼이 활성화된다)
2. 우측 상단 **`작업`** → **`탄력적 IP 주소 연결`**
3. **리소스 유형: 인스턴스**
4. **인스턴스** 드롭다운에서 만든 인스턴스 선택
5. 프라이빗 IP는 **비워둔다**
6. **`연결`**

### 2-3. 막힐 때

| 증상 | 원인 |
|---|---|
| `작업` 버튼이 회색 | IP를 **체크박스로 선택**하지 않았다 |
| 인스턴스 드롭다운이 비어 있음 | ① 리전이 다르다(가장 흔함) ② 인스턴스가 `실행 중`이 아니다 ③ 인스턴스가 실제로 생성되지 않았다 |
| 연결 시 오류 | 이미 다른 탄력적 IP가 붙어 있다 → **`재연결 허용`** 체크 |

### 2-4. 확인

**EC2 → 인스턴스 → 세부 정보**에서 `탄력적 IP 주소` 값이 보이면 완료다.
이 값이 다음 단계에서 DNS에 등록할 IP다.

⚠️ **할당만 하고 인스턴스에 연결하지 않으면 시간당 요금이 붙는다.**
실행 중인 인스턴스에 연결돼 있는 동안은 무료다. 당장 안 쓸 거면 차라리 릴리스한다.

## ③ 서브도메인 A 레코드 신청

사내 DNS 담당자에게 요청한다.

```
reminder.creamhouse.net    A    →    <탄력적 IP>
```

> ⚠️ **"외부 공개 DNS에 등록"을 반드시 명시할 것.**
>
> Let's Encrypt는 무료 인증서를 주기 전에 외부에서 도메인 소유를 확인한다.
> 사내망에서만 조회되는 도메인이면 **인증서 발급이 실패하고, HTTPS 없이는 PWA가 아예 동작하지 않는다.**
> 회사 보안 정책상 외부 노출에 별도 승인이 필요한지도 같이 확인한다.

### 확인 방법

```bash
nslookup reminder.creamhouse.net 8.8.8.8
```

⚠️ **조회 서버(`8.8.8.8`)를 반드시 지정해서 확인한다.**

레코드를 만들기 전에 조회한 적이 있으면, PC나 통신사 DNS에 "없음" 응답이 캐시돼 있어(네거티브 캐싱) **설정이 정상인데도 실패로 보인다.** 보통 5분~1시간이면 저절로 풀린다.

로컬 캐시만 지우려면:

```bash
ipconfig /flushdns
```

**공개 DNS에서 조회되면 배포를 진행해도 된다.** Let's Encrypt는 PC의 DNS를 쓰지 않고 권한 있는 네임서버에 직접 물어본다.

## ④ RDS 생성

단계가 많고 **나중에 못 바꾸는 항목**이 섞여 있다. 특히 `초기 데이터베이스 이름`을 빠뜨리는 실수가 잦다.

### 4-0. 메뉴 찾기

상단 검색창에 `RDS` 입력 → **`Aurora and RDS`** 클릭
(또는 `서비스` → `데이터베이스` → `Aurora and RDS`)

콘솔 메뉴 이름이 `Aurora and RDS`로 바뀌었지만, 우리가 만들 것은 **Aurora가 아니라 일반 RDS**다.

좌측 메뉴에서 **`데이터베이스`** → 우측 상단 **`데이터베이스 생성`**

> 좌측 메뉴가 안 보이면 좌측 상단 **☰** 아이콘을 눌러 펼친다.

생성 마법사는 아래 순서로 이어지고, 4-1~4-8이 그대로 대응한다.

```
1 생성 방식 → 2 엔진 옵션 → 3 템플릿 → 4 가용성 → 5 설정
→ 6 인스턴스 구성 → 7 스토리지 → 8 연결 → 9 인증 → 10 모니터링
→ 11 추가 구성 ▸ (접혀 있음)
```

### 4-1. 생성 방식

**`전체 구성`** 을 고른다. (예전 라벨은 `표준 생성`. AWS가 이름을 자주 바꾸므로 화면과 다를 수 있다.)

| 선택지 | 판단 |
|---|---|
| 빠른 구성 | ❌ 아래 항목들이 숨겨진다 |
| **전체 구성** | ✅ |
| S3에서 복원 | ❌ 기존 백업 복원용 |

`빠른 구성`은 **초기 데이터베이스 이름**을 지정할 수 없고, **퍼블릭 액세스**와 **스토리지 자동 조정**이 어떻게 설정됐는지 확인할 수 없다. 셋 다 우리가 반드시 제어해야 하는 항목이다.

### 4-2. 엔진

| 항목 | 값 |
|---|---|
| 엔진 유형 | **PostgreSQL** |
| 엔진 버전 | 기본 선택된 최신 안정 버전 |

> ⚠️ **`Amazon Aurora`를 고르지 말 것.**
> 메뉴 이름이 `Aurora and RDS`이고 목록 맨 위에 Aurora가 있어서 고르기 쉬운데,
> **Aurora는 프리 티어 대상이 아니고 최소 비용이 훨씬 크다.**
> `Amazon Aurora (PostgreSQL Compatible)`도 아니다. 그냥 **`PostgreSQL`** 이다.

로컬 개발은 Postgres 17로 하고 있다. RDS가 조금 낮은 버전이어도 이 앱이 쓰는 기능 범위에서는 문제없다.

### 4-3. 템플릿

**`프리 티어`** 를 고른다.

> ⚠️ **프리 티어 템플릿이 안 보일 수 있다.**
> 2025년 7월 이후 만든 계정은 크레딧 방식이라 이 항목이 없을 수 있다.
> 그럴 때는 **`개발/테스트`** 를 고르고, 인스턴스 크기를 아래 4-5에서 직접 `db.t4g.micro`로 지정한다.

**가용성 및 내구성**은 **`단일 DB 인스턴스`** 를 고른다. 다중 AZ는 비용이 두 배가 되고 이 프로젝트에는 필요 없다.

### 4-4. 설정

| 항목 | 값 |
|---|---|
| DB 인스턴스 식별자 | `reminder-db` |
| 마스터 사용자 이름 | `postgres` |
| 자격 증명 관리 | **자체 관리** |
| 마스터 암호 | 직접 입력 후 **따로 적어둔다** |

> ⚠️ **`AWS Secrets Manager에서 관리`를 고르지 말 것.**
> 시크릿 한 건당 월 $0.40가 별도로 나가고, 코드에서 꺼내 쓰는 절차도 추가된다.
> 이 규모에서는 `.env`에 직접 넣는 편이 낫다.

암호에 `@` `:` `/` 같은 문자가 들어가면 `DATABASE_URL`에서 URL 인코딩이 필요해 번거롭다. **영문·숫자 위주로 길게** 만드는 편이 편하다.

### 4-5. 인스턴스 구성

**버스터블 클래스** → **`db.t4g.micro`**

### 4-6. 스토리지

| 항목 | 값 |
|---|---|
| 스토리지 유형 | gp3 |
| 할당된 스토리지 | **20GB** |
| **스토리지 자동 조정** | **체크 해제** ⚠️ |

⚠️ 자동 조정을 켜두면 모르는 사이 스토리지가 늘어나고 **줄일 수는 없다.** 리마인더 앱 데이터는 20GB를 쓸 일이 없다.

### 4-7. 연결 — 여기가 핵심

> 💡 **`EC2 컴퓨팅 리소스에 연결`을 선택하면 가장 쉽다.**
> 만들어둔 EC2 인스턴스를 지정하면 AWS가 **VPC·서브넷·보안 그룹을 알아서 맞춰준다.**
> 4-9의 보안 그룹 수동 설정을 건너뛸 수 있다.

수동으로 할 경우:

| 항목 | 값 |
|---|---|
| 컴퓨팅 리소스 | EC2 컴퓨팅 리소스에 연결 안 함 |
| VPC | **EC2와 같은 VPC** |
| **퍼블릭 액세스** | **아니요** ⚠️ |
| VPC 보안 그룹 | 새로 생성 (`reminder-db-sg`) |
| 가용 영역 | 기본 설정 없음 |

⚠️ **퍼블릭 액세스를 `예`로 하면 인터넷에 DB가 열린다.** 몇 시간 안에 자동 스캐너가 붙는다. 우리 구성은 EC2에서만 붙으면 되므로 켤 이유가 없다.

⚠️ **VPC는 생성 후 변경이 사실상 불가능하다.** EC2와 같은 VPC인지 지금 확인한다.

### 4-8. 추가 구성 — 접어놓은 부분을 반드시 펼친다

**`추가 구성`** 을 클릭해 펼쳐야 나오는 항목이다.

| 항목 | 값 |
|---|---|
| **초기 데이터베이스 이름** | **`reminder`** ⚠️ |
| 자동 백업 | 활성화, 보존 기간 7일 |
| 암호화 | 활성화(기본값) |
| **Performance Insights** | **끄기** ⚠️ |
| **로그 내보내기** | **전부 체크 해제** ⚠️ |
| 마이너 버전 자동 업그레이드 | 켜기 |

> ⚠️⚠️ **`초기 데이터베이스 이름`을 비워두면 데이터베이스가 만들어지지 않는다.**
>
> RDS 인스턴스는 생기지만 그 안에 `reminder` 데이터베이스가 없어서,
> 마이그레이션 단계에서 `database "reminder" does not exist` 오류가 난다.
> **가장 흔한 실수이고, 접혀 있는 `추가 구성` 안에 있어서 놓치기 쉽다.**

⚠️ **Performance Insights와 로그 내보내기는 CloudWatch 과금**으로 이어진다. 이 프로젝트에는 필요 없다.

### 4-9. 생성 및 보안 그룹 설정

**`데이터베이스 생성`** 을 누르면 **5~10분** 걸린다. 상태가 `사용 가능`이 될 때까지 기다린다.

4-7에서 `EC2 컴퓨팅 리소스에 연결`을 골랐다면 이 단계는 건너뛴다.

수동으로 할 경우 — **RDS → 해당 DB → `연결 & 보안` → VPC 보안 그룹** 클릭 → **인바운드 규칙 편집** → 규칙 추가:

```
유형: PostgreSQL (5432)
소스: EC2의 보안 그룹 ID     ← IP가 아니라 보안 그룹 ID
```

⚠️ **IP가 아니라 보안 그룹 ID로 지정한다.** 그래야 EC2의 IP가 바뀌어도 연결이 유지되고, EC2에서만 접근이 허용된다.

### 4-10. 엔드포인트 확인

**RDS → 데이터베이스 → `reminder-db` → `연결 & 보안`** 에서 `엔드포인트` 주소를 복사한다.

```
reminder-db.xxxxxxxx.ap-northeast-2.rds.amazonaws.com
```

`.env`에 넣을 최종 형태:

```
DATABASE_URL=postgresql://postgres:<암호>@<엔드포인트>:5432/reminder?sslmode=require
```

### 4-11. 연결 테스트

EC2에 접속해서 확인한다. psql을 설치할 필요 없이 도커로 한 번만 띄우면 된다.

```bash
docker run --rm postgres:17-alpine \
  psql "postgresql://postgres:<암호>@<엔드포인트>:5432/reminder?sslmode=require" \
  -c "SELECT version();"
```

| 결과 | 의미 |
|---|---|
| 버전 문자열 출력 | ✅ 정상. 배포로 넘어간다 |
| `timeout` / 응답 없음 | 보안 그룹 인바운드 규칙이 없다 |
| `database "reminder" does not exist` | 4-8의 **초기 데이터베이스 이름**을 빠뜨렸다 (아래 참고) |
| `password authentication failed` | 암호가 틀렸거나 특수문자 인코딩 문제다 |

**초기 데이터베이스 이름을 빠뜨렸다면** 다시 만들 필요 없이 직접 생성하면 된다.

```bash
docker run --rm postgres:17-alpine \
  psql "postgresql://postgres:<암호>@<엔드포인트>:5432/postgres?sslmode=require" \
  -c "CREATE DATABASE reminder;"
```

## ⑤ 서버 접속 및 Docker 설치

Windows 10/11 에는 SSH 클라이언트가 내장돼 있다. PuTTY 같은 별도 프로그램이 필요 없다.

### 5-1. 키 파일 권한 (Windows 필수)

⚠️ 이 단계를 건너뛰면 거의 반드시 실패한다. 다운로드한 `.pem` 은 권한이 너무 열려 있어 SSH 가 거부한다.

```
WARNING: UNPROTECTED PRIVATE KEY FILE!
```

PowerShell 에서:

```powershell
icacls "$env:USERPROFILE\Downloads\key.pem" /inheritance:r
icacls "$env:USERPROFILE\Downloads\key.pem" /grant:r "$($env:USERNAME):(R)"
```

상속된 권한을 모두 제거하고, 본인에게만 읽기 권한을 준다.

### 5-2. 접속

```powershell
ssh -i "$env:USERPROFILE\Downloads\key.pem" ubuntu@<탄력적 IP>
```

사용자 이름은 AMI 에 따라 다르다. **Ubuntu → `ubuntu`**, Amazon Linux → `ec2-user`.
처음 접속 시 호스트 확인 질문에는 `yes` 를 입력한다.

### 5-3. 접속이 안 될 때

| 메시지 | 원인 |
|---|---|
| `UNPROTECTED PRIVATE KEY FILE` | 5-1 을 실행하지 않았다 |
| `Permission denied (publickey)` | 사용자 이름이 틀렸다 (`ubuntu` 확인) |
| `Connection timed out` | 보안 그룹 22번의 `내 IP` 가 옛 IP다 ⚠️ 아래 참고 |
| `Connection refused` | 인스턴스가 아직 부팅 중이다 |

⚠️ **`Connection timed out` 은 대부분 IP 변경 때문이다.**
보안 그룹 22번 규칙을 `내 IP` 로 설정했는데, 가정용 인터넷 IP 는 주기적으로 바뀌고
회사와 집을 오가면 당연히 달라진다.
**EC2 → 인스턴스 → 보안 → 보안 그룹 → 인바운드 규칙 편집** 에서 22번 소스를
**`내 IP` 로 다시 선택**하면 현재 IP 로 갱신된다.

### 5-4. MobaXterm 을 쓰는 경우

MobaXterm 은 자체 SSH 구현을 쓰므로 **5-1 의 키 권한 문제가 발생하지 않는다.**
PuTTY 와 달리 `.ppk` 변환도 필요 없고 `.pem` 을 그대로 쓴다.

1. `Session` → `SSH`
2. **Remote host**: 탄력적 IP
3. **Specify username** 체크 후 `ubuntu` 입력 (체크하지 않으면 Windows 계정명으로 시도해 실패한다)
4. `Advanced SSH settings` 탭 → **Use private key** 체크 → `.pem` 파일 선택
5. `OK`

접속하면 좌측에 SFTP 탐색기가 열린다.
`.env` 를 더블클릭하면 GUI 편집기로 수정할 수 있어, 긴 문자열(RDS 엔드포인트, VAPID 키)을
`nano` 로 붙여넣다 줄이 깨지는 사고를 피할 수 있다.

### 5-5. 최후 수단 — 브라우저 접속

키를 잃었거나 권한 문제가 안 풀릴 때 쓴다.

**EC2 → 인스턴스 선택 → `연결` → `EC2 인스턴스 연결` 탭 → `연결`**

브라우저에서 터미널이 열린다. 키 파일 없이 배포 명령을 모두 실행할 수 있다.

### 5-6. Docker 설치

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu
exit
```

⚠️ **그룹 반영을 위해 반드시 로그아웃 후 재접속한다.** 안 하면 `docker` 명령이 권한 오류를 낸다.

재접속 후 확인:

```bash
docker --version && docker compose version
```
